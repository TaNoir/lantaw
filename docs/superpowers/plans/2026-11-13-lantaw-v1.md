# Lantaw v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Lantaw v1. It's a local-first web app and PWA that forecasts a Filipino user's peso balance day by day for 12–24 months, with Timeline, Cutoffs, Plans, Kaya ba? and Items screens.

**Architecture:**
- A Rust crate (`engine/`) does every money, date and crypto decision: schedules, business-day shifting, projection, cutoffs, purchase comparison and encrypted backups. It's compiled to WASM with `wasm-pack --target web`.
- A Vite + Svelte 5 + TypeScript single-page app (`web/`) stores data in IndexedDB (Dexie), calls the engine, and draws hand-written SVG charts.
- There is no backend. Two keyless APIs (Frankfurter and Nager.Date) are fetched straight from the browser and cached.

**Tech Stack:**
- Rust (stable, MSVC host): `rust_decimal 1.43` with `serde-str`, `chrono 0.4.45` with `serde`, `serde 1`, `serde-wasm-bindgen 0.6.5`, `wasm-bindgen 0.2.130`, `argon2 0.6`, `aes-gcm 0.11`
- Web: Node 24, `svelte 5.57`, `vite 8.3`, `@sveltejs/vite-plugin-svelte 7`, `dexie 4.4`, `vite-plugin-pwa 2`, `vitest 5`, `fake-indexeddb 6`, `@playwright/test 1.65`, `@fontsource-variable/manrope`

**Spec:** `docs/superpowers/specs/2026-11-13-lantaw-design.md`. Read it alongside this plan. Approved mockups are in `.superpowers/brainstorm/683-1794516542/content/` (`home-layouts.html` and `screens-round2.html`).

## Global Constraints

**Money and dates**
- Money in Rust is `rust_decimal::Decimal`. Amounts cross into the engine as **decimal strings** (`"2083.33"`). Balances and amounts come out as **integer centavos (`i64`)**, which are plain JS numbers. `f64` is never used for money.
- Rounding to the centavo is `MidpointAwayFromZero`.
- Dates are `chrono::NaiveDate` and serialize as `"YYYY-MM-DD"`. "Today" is the device's local date, passed in from JS.
- Monthly occurrences are computed from the anchor (`start + n months`, clamped to the month's end), never by chaining from the previous date.
- Kinsenas means the 15th plus either the 30th or the last day. "30th" in February is Feb 28 or 29.
- A working day is Mon–Fri and not in the holiday set. Shift rules are `none`, `previous` or `next`, and they chain across consecutive holidays and weekends.
- The balance includes everything dated **before** `balanceAsOf`. Occurrences dated **on** `balanceAsOf` count as upcoming unless their item id is in `paidOnAsOf`.

**Privacy and dependencies**
- No user data leaves the device. The only network calls are `https://api.frankfurter.dev/v1/latest?base={CUR}&symbols=PHP` and `https://date.nager.at/api/v3/PublicHolidays/{year}/PH`. No analytics and no trackers.
- No backend or database server. Hosting is static Vercel. The WASM is built from source in CI and never committed.

**Visual design**
- Palette: Gulf ink `#0E2A3A` / `#0B2230`, Lagoon teal `#3FB8AF`, Mango `#F4A940`, Sunset coral `#E8604C`, Sand `#F4F1EA`. Dark by default, and the light theme follows the system setting.
- Manrope everywhere, self-hosted so it works offline. Amounts use tabular figures.
- Peso format: `₱12,480`, with centavos only when non-zero (`₱12,480.50`). Negatives are `−₱1,240` (U+2212 minus).
- Respect `prefers-reduced-motion`, and make everything keyboard-operable.
- Performance: a full 24-month `project` call runs in under 10ms on a mid-range phone, and scrubbing reads the precomputed `days` without recomputing. Checked in Task 13.
- Body text is at least 14px and all text meets WCAG AA contrast. Text is never faded with `opacity`. What-if items use italics and a dashed icon outline.
- Copy uses Filipino terms with English hints: sweldo, kinsenas, hulog, gipit, "Kaya ba?", Kaya / Gipit / Hindi kaya.
- Navigation: five tabs (Timeline, Cutoffs, Plans, Kaya ba?, Items) plus Settings behind a gear icon. Phones get a bottom tab bar; at 1024px and wider it becomes a left rail.
- Defaults: horizon 12 months (choice of 12 or 24), safety buffer ₱3,000, card FX fee 0%, Davao City holidays on, theme System.

**Repository and toolchain**
- The repo root is `D:\Project 2`. Run commands from the repo root unless a step says otherwise.
- Commits are local only, and nothing is ever pushed. Every commit ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The Bash tool is Git Bash on Windows, so use POSIX syntax.

## Review Focus

1. **Coming back weeks later.** If `balanceAsOf` is old, or `today` is past the horizon, the forecast still renders. `expectedToday` is `None` when today is outside the horizon, and the stale prompt appears after 7 days. *Tested in Task 6 and Task 13.*
2. **Empty or partial setup.** With no items, or no main sweldo, there's a flat line, the cutoffs fall back to the 15th and last day, and there's no crash. *Tested in Task 6.*
3. **Messy amount input.** `"1,000"`, `" 1000.5 "`, `"-5"`, `""`, `"abc"`, and amounts of ₱1,000,000,000,000 or more are normalised or rejected with a message. They never reach the engine as garbage. *Task 10 and Task 15.*
4. **Foreign-currency item while offline with no cached rate.** The engine returns `MissingFxRate("USD")` and the UI asks for a manual rate instead of showing a blank screen. *Task 4 and Task 12.*
5. **Bad backup file.** A wrong passphrase, a tampered file, a non-Lantaw JSON file, or a newer `version` each give a clear error, and local data stays untouched. *Task 8 and Task 18.*

### Task 3: Calendar and schedules

**Files:**
- Create: `engine/src/calendar.rs`, `engine/src/schedule.rs`

**Interfaces:**
- Produces:
  - `calendar::HolidaySet::new(dates: &[NaiveDate]) -> HolidaySet`
  - `HolidaySet::is_working_day(&self, d: NaiveDate) -> bool`
  - `HolidaySet::shift(&self, d: NaiveDate, rule: BusinessDayRule) -> NaiveDate`
  - `schedule::dates(s: &Schedule) -> impl Iterator<Item = NaiveDate> + '_`. This gives nominal dates from `s.start` onwards in ascending order, stops after `s.end` (inclusive) when it's set, and is infinite otherwise. `Once` yields `start` only.

Anchor rules for each cadence:
- **Weekly and EveryTwoWeeks:** `start + 7k` and `start + 14k` days.
- **Monthly{day}:** for n = 0, 1, …, the date `(start's year-month + n months)` with day `min(day, last day of that month)`, keeping only dates ≥ `start`.
- **Kinsenas:** for each month from start's month, emit the 15th, then the second payday (`min(30, last day)` for `Thirtieth`, the last day for `LastDay`), keeping only dates ≥ `start`.
- **Yearly{month, day}:** each year from start's year, clamped to the month's end, keeping only dates ≥ `start`.

### Task 4: Expanding items into events

**Files:**
- Create: `engine/src/expand.rs`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `pub struct Ctx<'a> { pub as_of: NaiveDate, pub horizon_end: NaiveDate /* exclusive */, pub holidays: &'a HolidaySet, pub fx: &'a [FxRate], pub fee_pct: Decimal, pub paid_on_as_of: &'a HashSet<String> }`
  - `pub fn expand(item: &Item, ctx: &Ctx) -> Result<Vec<Event>, EngineError>`

Rules:
- An occurrence is **in the forecast** if its *shifted* date `d` satisfies `as_of < d < horizon_end`, or `d == as_of` and the item id is not in `paid_on_as_of`.
- **Sign:** Income → +. Bill and Installment → −. OneOff → by its direction. Paluwagan → − on every round except `my_turn`, which is `+ amount × (members − 1)`.
- **Installment:** the occurrences are the first `total_payments` dates of the schedule. If `paid_override = Some(k)`, the remaining payments are the first `total_payments − k` in-forecast occurrences, and the notes count from k+1. Otherwise only in-forecast occurrences are emitted, and the note is `"{i} of {n}"` with i the 1-based position among all `total_payments`.
- **Paluwagan:** rounds are the first `members` dates. The note is `"turn {r} of {N}"`, or `"payout"` on `my_turn`.
- **FX:** if `currency != "PHP"`, the amount becomes `to_centavos(convert_to_php(amount, rate, fee_pct))`. If there's no `FxRate` for that currency, return `Err(MissingFxRate(currency))`.
- **Moved dates:** when the shifted date differs from the nominal date, `note` gets ` · moved from {Dow Mon D}` appended (for example, "moved from Sun Nov 15").
- `Event.included` copies `item.included`.

### Task 5: Cutoffs

**Files:**
- Create: `engine/src/cutoffs.rs`

**Interfaces:**
- Produces: `pub fn build_cutoffs(paydays: &[(NaiveDate /*nominal*/, NaiveDate /*shifted*/)], events: &[Event], days: &[i64], start: NaiveDate, horizon_end: NaiveDate) -> Vec<Cutoff>`.
- Task 6's `project` builds `paydays` from the main-sweldo item's schedule dates (nominal and shifted), within `[start, horizon_end)`, with no as-of filtering. If there's no main sweldo, it uses Kinsenas `LastDay` nominal dates with no shifting. That fallback is tested in Task 6.

Rules:
- Cutoff *i* covers `[payday_i, payday_{i+1} − 1]`. The last cutoff ends at `horizon_end − 1`.

- `income` and `outflow` are sums of the *included* events in the window. `outflow` is reported as a positive number.
- `left_centavos = days[end − start]`.
- `event_indices` point into `events` and include excluded events, so the UI can show them dimmed.

- `horizon_end = start + horizon_months months` (exclusive), so `days.len()` is the number of days in `[start, horizon_end)`.
- `days[i]` is the balance at the **end** of day `start + i`. It starts from `to_centavos(balance)` plus all *included* events on or before that day.
- `events` holds every expanded event, sorted by `(date, item order)`. That includes the excluded ones, with `included: false`.
- `what_if_days` is `Some(series with all items included)` if any item has `included == false`, otherwise `None`.
- `gipit` is the minimum of `days`, taking the earliest date on a tie. Its `causes` are the item ids of the outflow events inside the cutoff that contains the gipit date, sorted by amount (largest first), with at most 3.
- `first_below_buffer` and `first_below_zero` are the first day with a balance below the buffer or below 0.
- `month_ends` are the balances on the last day of each month in range (including a partial last month at its final day).
- `finish_lines`: one per Installment (and per Paluwagan, using its last round) whose last occurrence falls inside the horizon. `frees_per_month_centavos` is the monthly equivalent of the payment: Monthly ×1, Kinsenas ×2, Weekly ×52/12 and EveryTwoWeeks ×26/12, both rounded half away from zero, and Yearly ×1/12.
- `expected_today` is `days[today − start]` when `start ≤ today < horizon_end`, otherwise `None`.

### Task 7: Kaya ba? comparison

**Files:**
- Create: `engine/src/compare.rs`

**Interfaces:**
- Consumes: `project` and `expand`.
- Produces:

```rust
pub struct Purchase { pub name: String, pub price: Money, pub date: NaiveDate, pub options: Vec<PayOption> }
pub enum PayOption { Cash, Installment { months: u32, monthly: Option<Money> } }   // tag "type": "cash" | "installment"
pub enum Verdict { Kaya, Gipit, HindiKaya }                                        // "kaya" | "gipit" | "hindiKaya"
pub struct OptionResult { pub label: String, pub option: PayOption, pub verdict: Verdict, pub lowest: LowPoint,
    pub days_below_buffer: u32, pub days_below_zero: u32, pub total_paid_centavos: i64,
    pub add_on_centavos: i64, pub monthly_centavos: Option<i64> }
pub struct BestDate { pub date: NaiveDate, pub reason: Option<String>, pub lowest_after: LowPoint }
pub struct Comparison { pub best_cash_date: Option<BestDate>, pub options: Vec<OptionResult> /* sorted */ }
pub fn compare_purchase(input: &Input, p: &Purchase) -> Result<Comparison, EngineError>
```

Rules:
- Each option is a temporary item added on top of the baseline `project` (included items only).
- **Cash** is a OneOff Out on `p.date`.
- **Installment** payments are monthly starting one month after `p.date`, anchored with the Monthly rule. When `monthly` is `None`, each payment is `price / months` rounded to the centavo, and the **last** payment absorbs the remainder so the total equals the price exactly.
- `lowest` is taken over the days from `p.date` onwards.
- **Verdict:**
  - Kaya if `days_below_buffer == 0`
  - HindiKaya if `days_below_zero > 30`
  - Gipit otherwise
- **Labels:**
  - `"Cash on {Mon D}"`
  - `"{n} × ₱{x}"` when the payments add up to the price
  - `"{n} × ₱{x} (+₱{add})"` when there's an add-on
- **Sort order:** by `lowest.centavos` (highest first), then by `total_paid` (lowest first).
- **Best cash date:** use the baseline `days` and scan D from `max(p.date, start)` up to the horizon. Pick the first D where `min(days[D..]) − price ≥ buffer`.
  - `reason` is `"right after your {name}"`, where name belongs to the largest inflow event in `(p.date, D]`. It's `None` when D equals `p.date`.
  - `lowest_after` is computed with the purchase applied.
  - If no D qualifies, the result is `None`.

### Task 18: Settings, backup and theme

**Files:**
- Create: `web/src/lib/backup.ts`, `web/src/screens/Settings.svelte`
- Test: `web/src/lib/backup.test.ts`

**Interfaces:**
- `type BackupData = { settings: AppSettings; items: StoredItem[] }`
- `type BackupFile = { format: 'lantaw-backup'; version: 1; createdAt: string; kdf: { alg: 'argon2id'; m: number; t: number; p: number; salt: string /*b64*/ }; nonce: string /*b64*/; ciphertext: string /*b64*/ }`
- `exportBackup(data: BackupData, passphrase: string, kdf = { m: 19456, t: 2, p: 1 }): Promise<{ filename: string; blob: Blob }>`. The filename is `lantaw-backup-YYYY-MM-DD.lantaw`. Salt (16 bytes) and nonce (12 bytes) come from `crypto.getRandomValues`.
- `importBackup(text: string, passphrase: string): Promise<BackupData>`. It throws `BackupImportError` with code `'NOT_LANTAW' | 'NEWER_VERSION' | 'WRONG_PASSPHRASE'`.
- `mergeItems(local: StoredItem[], incoming: StoredItem[]): StoredItem[]`. Items are matched by `id` and the newer `updatedAt` wins. Afterwards `setMainSweldo` keeps the newest main flag.

**Settings UI** (`screens-round2.html` section 3):
- Balance and as-of date. Saving this opens the "Already in your balance?" checklist.
- Buffer, a 12/24 horizon picker, Davao holidays toggle, custom holidays list, card FX fee, and the USD rate with its date and a refresh button.
- Theme picker (System, Dark, Light), which sets `document.documentElement.dataset.theme`.
- Export: asks for the passphrase twice, then shows the warning "If you forget this password, the backup can't be opened."
- Import: a file picker and passphrase, then Replace or Merge.
- Erase everything, behind a typed confirmation of "BURAHON".
- The line "🔒 Stored only on this device".
